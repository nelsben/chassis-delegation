## Why

Building is delegated but merging is not: 51% of the brain's 1148 shell calls this month were the same fifteen-step merge pipeline typed by hand after every consistent verdict (rebase the worktree, copy the card in as merged, run the three gates, push, open and merge the PR, diff and remove the root card, pull, remove the worktree and branches, tag a release when the version bumped, pull the loaded clone). It is slow, it is where the brain's few hand mistakes happen, and it costs premium-model tokens on rote work. The mod's hard allowlist stays: the mod never pushes, never calls gh and never touches the network, so the command does every local step itself and prints the remote steps as one block the brain runs verbatim, the way dispatch prints the Agent call.

## Done when

- PREPARE. `/delegation merge <ID>` (command and, when the mod registers tools, a `merge` tool with task=<ID>) refuses with one line unless all of these hold: the task's latest ledger row is consistent with next=accept (else `<ID>: last verdict is <verdict> · next=<next>; merge needs consistent/accept`), the task's worktree exists on its branch with a clean tree (else which file is dirty), and the session's main checkout is on its default branch with no tracked changes (untracked files are fine; the root card file is expected). Then, in the worktree, by argv with no shell: `git fetch origin`; `git rebase <baseRef>` (origin/main by default, as the mod resolves it); on a conflict it aborts the rebase and answers `<ID>: rebase onto origin/main conflicts in <files>; resolve by hand`.
- MERGED CARD. The root card `<cardDir>/<ID>-*.md` is copied into the worktree at the same path with `status: merged` in its front matter (a `## Review` section, when the brain passes `--review <text>` or `--review-file <abs path>`, is appended), and committed as `cards: <ID> merged`, with a `Co-Authored-By: Claude <model name> <noreply@anthropic.com>` trailer built from the host's model id when the mod can name it (the alias machinery in hooks/lib/watch.ts), else no trailer. When the worktree already carries a merged card for the id, nothing is committed again.
- GATES. The card's gates (gateMap, the same runner verification uses, by argv, no shell) run in the worktree at the new head; a failing gate answers `<ID>: gate <id> failed at <sha>; not pushed` with the last 20 lines of its output, and the command stops there. Gate output goes to `.delegation/<ID>/merge-gates.txt`.
- THE REMOTE BLOCK. After the gates pass the command writes `.delegation/<ID>/pr.md` (title from the card title; body: the card's Done-when bullets as a checklist, the verdict line, the gate results, and the trailing line `🤖 Generated with [Claude Code](https://claude.com/claude-code)`; no absolute paths and no machine or user names in it) and prints, as the dispatch tool prints the spawn block, one fenced block of exactly these lines for the brain to run verbatim: `git -C <worktree> push -u origin <branch>`, `gh pr create --repo <owner/repo> --base <default branch> --head <branch> --title <title> --body-file <abs pr.md>`, `gh pr merge --repo <owner/repo> <branch> --rebase`, then `/delegation merge <ID> --finish`. The mod itself never runs git push, gh, curl or any network command (hooks/lib/allow.ts is not touched and a test holds that no argv the command runs starts with those).
- FINISH. `/delegation merge <ID> --finish` runs `git fetch origin` in the main checkout and refuses with `<ID>: <branch> is not in origin/<default> yet` unless the worktree's head commit (or its rebased twin: same tree, same subject) is an ancestor of origin/<default>. Then it: compares the merged card on origin/<default> with the root card (status aside; the Review section may be extra) and removes the root card only when they match, else answers which lines differ and leaves it; runs `git pull --ff-only` in the main checkout; removes the worktree (`git worktree remove`) and the local branch; marks the task record `merged` with the merge sha and writes a ledger row `{kind: 'merged', task, sha, pr?: n}`; and prints a second block of remote lines: `git push origin --delete <branch>`, and, when the rebased commits changed `hooks/lib/version.ts` (MOD_VERSION), `git tag -a v<version> -m v<version>`, `git push origin v<version>`, and `git -C <loaded clone> pull --ff-only` where <loaded clone> is `$.plugin.root` when it is a git checkout other than the session root. It ends with `<ID> merged at <sha>` and, when a version bumped, `release v<version>: run the block above, then reload the window`.
- STATUS. `/delegation` lists a merged task under `merged:` for the rest of the session (id, sha, version if bumped); the `running:` section no longer shows it.
- TESTS. tests/merge.test.ts holds engine cases: the three refusals (verdict not consistent, dirty worktree, main checkout with tracked changes), the rebase conflict, the gate failure, the happy path asserting the exact argv sequence and the printed block, --finish before the merge landed, --finish happy path with and without a version bump, the card-mismatch case, and a case that greps every argv the command ran for push/gh/curl/sf and finds none. The three gates pass and no existing test is deleted.
- DOCS. README: a `## Merging a card` section (what the command does, what it refuses, the two blocks, the allowlist rule) and the command table rows; CHANGELOG.md entry under `## Unreleased` above the latest version heading (create it if missing). The hand-back lists every step of the old by-hand pipeline the command does NOT do, so the brain knows what is left.
