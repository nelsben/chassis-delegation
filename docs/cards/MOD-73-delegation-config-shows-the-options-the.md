## Why

The config surface grew by accretion and no longer makes sense to its one user. Live, in the VS Code extension, the host has no settings rows for a folder-loaded mod, so 30 of the 49 options have never been changeable and all run at their defaults; the other 19 are set only by hand-editing .chassis-delegation.json. The list shows the manifest layer, not what the mod runs with: it says `gateMap = "" (default)` and `maxWorkers = 0 (default)` while the repo file sets three gates and 3 workers. It prints 110 lines of raw values, names are case-sensitive with no suggestion, durations and dollars are bare numbers, and 11 options are never set to a non-default value by any test. This card makes config one thing: the effective option set, shown short and human, settable anywhere, and measured.

## Done when

- ONE TRUTH. hooks/lib/configcmd.ts (and new hooks/lib/config*.ts files as needed) resolve every manifest userConfig field to its EFFECTIVE value and SOURCE, the same values the mod's own Config/Effective use, so `/delegation config` can never disagree with /delegation status. Source is one of: default (the built-in, e.g. maxWorkers 2, tierMap economy→haiku; never the manifest's empty sentinel), repo (.chassis-delegation.json), yours (the user options file below), host (a Claude Code settings row), locked (a locked host row). Precedence low→high: default < repo < yours < host, except a host value that is unset (its manifest sentinel: '', 0, false as settingsLayer reads today) counts as absent. The existing mergeConfig/settingsLayer semantics for repo keys are preserved; maps still merge per key.
- SETTABLE EVERYWHERE. A user options file `~/.claude/chassis-delegation/options.json` (HOME via $.env.get) holds `{ "<field>": <value> }` for any manifest field. The mod reads it where it reads the activation options, and rereads it when it changes, so a set applies from the next hook without a reload. `/delegation config <field> <value>` writes the parsed value there when the host has no row for the field (or $.config.set is denied/throws for 'no /config row'); when the host has a row it calls $.config.set as now. It answers `<field> = <shown value> (yours)` or `(host)`. `/delegation config <field> default` removes the key from the user file (or sets the host row to its manifest default). `/delegation config repo <field> <value>` writes a repo-scoped field into <root>/.chassis-delegation.json (keeping the file's other keys and `_` comment keys, 2-space JSON) and answers `<field> = <shown value> (repo)`; for a non-repo field it refuses and says the field is personal. A locked field refuses with `<field> is locked by policy`. A malformed user file is reported once by toast and in the debug log, and ignored.
- SCOPE. Every field has a scope in the table: repo (the 19 REPO_KEYS plus issueRepo if it is a manifest field) or user (the rest). The show view says `scope: repo (set with /delegation config repo <field> <value>; also from your options)` or `scope: user`.
- NAMES. Field names match in any case (`maxworkers` finds maxWorkers). An unknown name answers `no option "<typed>"; did you mean <field>?` when a field is within Damerau-Levenshtein distance 3 or shares a case-insensitive prefix of 4+ letters; else `no option "<typed>"; /delegation config all lists them`.
- SHORT BY DEFAULT. `/delegation config` prints: line 1 `chassis-delegation: <N> options, <k> set (<a> repo, <b> yours, <c> host, <d> locked)`; then only the SET fields (source != default), grouped under the MOD-70 headings, one line each ` <field> = <shown> (<source>)`, with no summaries; groups with nothing set are omitted; then one line `all: /delegation config all · one group: /delegation config <group> · one: /delegation config <field> · set: /delegation config <field> <value>`. With nothing set it prints line 1 plus `all 49 at their defaults` plus the how-to line, and nothing else. `/delegation config all` prints every field grouped, each as `<field> = <shown> (<source>)` with the MOD-70 summary on the next line indented. `/delegation config <group>` (group matched by its first word, any case: workers, checking, where, debriefs, evals, guards, display) prints that group in the `all` shape. Reserved words (all, repo, default, the group words) are never field names. The no-rows line from MOD-68 is removed; the host having no rows is normal.
- HUMAN VALUES. Rendering is by a per-field kind in the table, not by JSON: booleans as on/off; minutes as `20 min`, hours as `6 h`; dollars as `$10` (`no cap` for 0); tokens as `200K`; maps as `economy→haiku, standard→sonnet, frontier→opus` (gateMap as its ids only, e.g. `validate, node, test`; the show view prints each command on its own line); lists comma-joined; empty text as `(none)`; a model-alias or agent-type as itself. A line is at most 100 characters, cut with …; the show view holds the whole value. The show view also prints an `in effect:` line when the mod's behaviour differs from the stored value: autoEval on but evalCommand empty → `in effect: off (no evalCommand)`; reviewTier empty → `in effect: one tier below the worker`; maxWorkers 0 → `in effect: 2`. The worker finds and lists every such derived case in the hand-back.
- MEASURED. tests/options.test.ts holds ONE engine case per manifest field: it sets the field to a non-default value through `/delegation config <field> <value>` (host rows absent) and asserts an observable change in the mod's behaviour or output (a brief header, a verdict row, a status line, a refused write, a toast, a timing decision via the fake clock; the summary line `k set` alone does not count). A node test holds the table complete both ways against the manifest and holds that tests/options.test.ts names every field. A field whose change has NO observable effect through any hook is not faked: its case is `test.skip` with a reason, and the hand-back lists these under `candidates for removal` with the reason. The worker also lists any option whose summary (MOD-70 table) it found untrue and corrects it.
- DOCS. README's /delegation config section is rewritten to this design: the one-line default view, all/group/field/set/repo/default forms, the user options file path and precedence, the scope rule. CHANGELOG.md has an entry under `## Unreleased` above the latest version heading (create the heading if there is none). The three gates pass and no existing test is deleted; tests whose expectations change are updated to the new shapes.
