## Why

On a subscription the thing that runs out is the seven-day rate-limit window, not dollars: the host pushes each window's percentUsed and resetsAt on session.measure, and the mod already draws a "window –" tile it never fills. A per-day share of what is left in the window, shown in the prompt footer where the eye already rests, lets the person ration the week instead of discovering at 86% that two days remain. Dollars at list price stay the worker meter; this meter is in window points.

The rows the mod draws above the prompt today (the `N workers · $x · ctx N%` status line and the band) have proved noise: the verdict row, the toasts and the dashboard pane already carry that information when it is wanted. This card retires the status line and turns the band off by default, so the only standing mark the mod leaves on the prompt is the meter in the footer.

## Done when

- Two user-scope options in .claude-plugin/plugin.json userConfig, in hooks/lib/configtable.ts (group Display) and hooks/lib/configcmd.ts: `ration` (choice: seven_day, five_hour, off; default seven_day) names the window the meter reads, and `rationDaily` (number, default 0) is a fixed daily allowance in window points; 0 means pace-to-reset. The existing config tests that hold the table complete both ways still pass.
- A pure module hooks/lib/ration.ts: `dayKey(now)` is the local YYYY-MM-DD; `dayRecord` folds a reading {percentUsed, resetsAt} at `now` into today's record {startPct, startAt, resetsAt, lastPct, lastAt, used} (startPct is the first reading of the day, or 0 from the moment resetsAt changes because the window reset today; used = lastPct - startPct, never negative); `allowance(record, option)` is rationDaily when set, else (100 - startPct) / daysLeft where daysLeft is the window's remaining days counted from the day's start, fractional days rounded up, at least 1; `pace(record, allowance, now)` is `on pace` while used <= allowance * elapsedFractionOfDay + 0.5, `ahead by <x>` past that, `over by <x>` once used >= allowance, with x to one decimal; with rationDaily set, `surplus(records, rationDaily)` sums (rationDaily - used) over this window's earlier days, floored at 0, and is added to today's allowance.
- The health bar, pure in hooks/lib/ration.ts: `segments(kind)` is 7 for seven_day (one cell per day of the window, counted from resetsAt minus seven days, oldest on the left) and 5 for five_hour (one per hour); `bar(percentUsed, segments)` is one glyph per cell: the window's used points fill the cells left to right, `█` for a cell wholly used, one of the eighth blocks `▏▎▍▌▋▊▉` for the cell the used points run out in (rounded to the nearest eighth; a zero eighth is `░`), `░` for the rest, so `bar(41, 7)` is `██▉░░░░` and `bar(100, 7)` is `███████`; `dayIndex(now, resetsAt, segments)` is the 1-based cell today falls in. The bar reads as health: the cells still `░` are the days' worth of window left, and fill running past today's cell is the week being spent faster than its days. `rationText(window, record, allowance, pace, now)` renders `<bar> <pct>% · day <d>/<segments> · today <used>/<allowance> · <pace>`, e.g. `██▉░░░░ 41% · day 3/7 · today 6.2/8.4 · on pace` (`hour` in place of `day` for five_hour; `(+1.2)` after the allowance when a surplus applies). `rationReport(...)` renders the /delegation ration text: the bar line with `resets 2d 4h` appended, today's line, and the window's days so far as `Mon 12.1 · Tue 9.0 · …` from the stored records (`–` for a day without one, today marked `*`). `daySegments(records, today, allowancePerDay)` gives the pane one entry per cell: {used, share, state} with state `under` (used <= share), `near` (within 10% over), `over`, `today`, or `future`.
- hooks/register.ts: the session.measure handler folds e.rateLimits into the store under `delegation.ration.<kind>.<YYYY-MM-DD>` for every window kind reported (one write per measure whose rateLimits changed, values idempotent so two sessions writing the same key agree), keeps the latest rateLimits in memory, and calls `$.ui.invalidate('ui.render')` so the footer redraws. A `ui.render` handler on component `SessionMode` (the dim mode labels at the right of the prompt footer, drawn on the terminal and the desktop) passes the element on with rationText appended to `modes` when `ration` is not off and the chosen window has a reading; with no reading, or `ration: off`, it passes `next(e)` unchanged. The label is plain text (no tree of its own), so it reads the same on both surfaces. On the first measure of a session the handler also reads `$.session.usage().rateLimits` so the footer does not wait for a whole-point move. `/delegation ration` prints rationReport; `/delegation` summary adds one `ration: …` line after the brain spend line. The dashboard's Spend tile gets the latest rateLimits so it shows the real window instead of `window –`, and the pane (hooks/lib/pane.tsx) draws the bar under that tile in the style of brainBar: one `Box` per cell, each three `█` wide, coloured by daySegments' state (green under, yellow near, red over, the current cell at its partial fill in the scheme's accent, future cells dimColor), with the text `59% left · resets 2d 4h` beside it; a cell for a day before the mod had a record is drawn dim with `?`.
- The host status line is retired: register.ts no longer calls `$.ui.status` with text (one `$.ui.status(undefined)` at session start clears a line a previous version pinned); `statusText`, `shouldClearStatus`, STATUS_EVERY_MS, STATUS_IDLE_MS and the refreshStatus timer go, with hooks/lib/watch.ts keeping only what else still uses it. The `dashboardBand` option stays but its default becomes false in plugin.json, configtable.ts and configcmd.ts (the default note reads `off: no band above the prompt`); the band's draw path is unchanged when a person turns it on, and the pane stays reachable through `/delegation dashboard`. Nothing else the mod draws above the prompt is touched (notices, toasts, verdict rows stay).
- hooks/lib/retention.ts keeps `delegation.ration.*` records 14 days by their lastAt and never groups them under a task.
- Tests: pure tests in tests/node/ration.node.mjs for dayKey, dayRecord (first reading, later readings, a reset mid-day), allowance (pace-to-reset with 1 to 7 days left, rounding, rationDaily), pace (the three states and the boundary), surplus, bar (0, 41, 100, a five-cell window, the eighth rounding), dayIndex (first day, last day, the reset moment), daySegments (each state), rationText and rationReport (exact strings). Engine tests in tests/ration.test.ts: a session.measure carrying seven_day 41% writes the day record and a SessionMode render passes on modes with the meter label appended after the host's; a second measure the same day raises used; `ration: off` passes the modes unchanged; with no reading the modes pass unchanged; `/delegation ration` prints the report; the Spend tile names `seven_day window 41%`; the pane render holds seven bar cells with the expected colours for a seeded week of records; across a whole session `$.ui.status` is called with text zero times; the band is not drawn on defaults and is drawn with `dashboardBand: true`. The existing status-line tests in tests/watch.test.ts, tests/hooks.test.ts and tests/dashboard.test.ts that assert the `N workers · $x · ctx N%` text or the idle clear are removed or inverted (the line is never pinned); tests that read the band on defaults set `dashboardBand: true` first.
