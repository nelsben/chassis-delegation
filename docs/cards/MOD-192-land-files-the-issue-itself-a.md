## Why

The founder plans in Claude, not on GitHub; the mod must keep GitHub in step so context is not lost. Today /delegation land (MOD-190) only writes the body and prints the gh issue create line for a human to run, and the brain has no tool to land with at all. This card makes landing one call that files the issue, labels it, hangs it under its parent and adds it to the configured Project.

## Done when

- A new model-callable tool named land is registered in session.start beside the card/dispatch/merge tools (same try/debug pattern), with inputSchema {type (enum feature|epic|story|task|bug|spike, required), title (string, required), parent (number, optional, whole number 1+), paths (string array, optional), note (string, optional), dryRun (boolean, optional)}; its description says it files a GitHub issue in this repo for work that came up mid-session, labelled type:<type>, under the parent when given, added to the configured Project, and that dryRun only writes the body and prints the line. It is answered by the same code path as /delegation land (factor runLand so both call one function); the slash command gains a --dry-run flag parsed by parseLandArgs in hooks/lib/land.ts.
- Without dryRun, after writing the landed body exactly as today, land runs through the existing run() helper (never $.process.run directly): gh issue create --repo <owner/name from origin> --title <title> --label type:<type> [--parent <n>] --body-file <the landed file>. It takes the issue url from stdout (the last line matching ^https://github.com/<owner/name>/issues/<digits>$), and when the new option project is set to <owner>/<number> it then runs gh project item-add <number> --owner <owner> --url <that url>. It appends one line `issue: #<n> <url>` to the end of the landed file. The text it returns names the file, `filed #<n> <url>`, `added to project <owner>/<number>` when it was, and keeps the parent hint line; it drops the line 'nothing was filed or dispatched' (dryRun keeps today's output exactly, that line included).
- When gh issue create fails (non-zero exit, or no url on stdout) land returns the file path, the gh line it tried, and gh's stderr trimmed to 400 characters, and writes nothing back; when only the item-add fails it still reports `filed #<n>` and adds `not added to project <owner>/<number>: <stderr>`. When origin is not a GitHub remote it behaves as dryRun and says why.
- hooks/lib/allow.ts gains exactly two shapes, documented in the header comment list beside MOD-7's: (a) gh issue create --repo <landRepo> --title <t> --label type:<feature|epic|story|task|bug|spike> [--parent <1-9 digits>] --body-file <absolute file under <root>/.delegation/landed/, plain segments, ending .md>, args in exactly that order, the title non-empty and not starting with '-'; (b) gh project item-add <1-9 digits> --owner <projectOwner> --url https://github.com/<landRepo>/issues/<1-9 digits>, where the digits after item-add equal the configured project number. AllowConfig gains landRepo?: string (owner/name, the session root's origin, filled in allowCfg) and project?: { owner: string; number: number }; either absent = its shape is refused. The MOD-7 issueRepo shapes are unchanged and still checked first; a create that matches neither shape is refused with a message naming both shapes. Nothing else is added to the list: no gh issue edit/close, no other gh project verb.
- landRepo in allowCfg is the owner/name of the session root's origin read from <root>/.git/config with gitConfigValue + ownerRepoOf (as runLand reads it today), cached the way the other allowCfg inputs are; it is empty when origin is not GitHub.
- A new string option project (title 'GitHub Project (owner/number)', default "") is added to .claude-plugin/plugin.json userConfig, read by hooks/lib/repoconfig.ts from .chassis-delegation.json the same way scopeAmends is (a value in /config other than the default wins), listed in hooks/lib/configtable.ts so /delegation config project <owner/number> sets it, and validated as ^[A-Za-z0-9-]+/[0-9]{1,9}$ (anything else is treated as unset, with a debug line). tests/options.test.ts covers the parse.
- docs/guide.md 'Planning on GitHub' section: land now files (tool and command), --dry-run / dryRun keep the old print-only behaviour, the project option, and that the labels type:* must exist in the repo. docs/configuration.md documents project. docs/contracts.md lists the two new allowlist shapes if it lists MOD-7's. CHANGELOG.md gets an Unreleased entry.
- The gates pass: claude plugin validate, the node suite, claude plugin test.
